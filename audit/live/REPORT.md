# Live Codex CLI versus Knodexa pilot

2026-10-13. Actual authenticated Codex sessions, model `gpt-6.1-sol`, low
reasoning effort, CLI `0.162.0-alpha.17.2`. Synthetic task fixture; real
model-generated code and independently checked results. One implementation
trial per arm. The agent sessions ran in disposable projects and did not edit
this repository's application source.

## Observed results

| Arm | Independent cases | Input tokens | Cached input | Uncached input | Output tokens | Wall time |
|---|---:|---:|---:|---:|---:|---:|
| native_fresh | 20/20 | 62,992 | 54,784 | 8,208 | 1,506 | 53.90s |
| knodexa_fresh | 20/20 | 80,884 | 74,880 | 6,004 | 1,361 | 77.87s |
| native_resumed | 20/20 | 96,530 | 90,368 | 6,162 | 1,413 | 62.39s |

The resumed implementation row excludes the seed turn. The seed consumed
14,916 input tokens (12,288 cached), 5 output tokens, and 7.99 seconds.
Including the seed, native resume consumed 111,446 input tokens, 1,418 output
tokens, and 70.38 seconds. Seed preparation costs for the checked-in native
file memory and canonical Knodexa records were not measured; they were fixture
setup, not model-generated history.

All arms passed. In the matched fresh-session comparison, Knodexa used 28.4%
more reported input tokens and took 44.5% longer. It used fewer uncached input
tokens and fewer output tokens. Cache warmth, call count, and run-to-run latency
vary, so these observations do not establish a price advantage or statistical
performance difference. There was no demonstrated correctness advantage for
Knodexa in this pilot.

## What was compared

- Native fresh: Codex reads AGENTS.md and uses its normal shell/file tools to
  inspect a PROJECT_MEMORY.md containing requirements, a prior failure, a lesson,
  and 20 unrelated image-task entries.
- Knodexa fresh: same coding task, relevant facts, and 20 unrelated image lessons,
  stored in canonical task/decision/failure/lesson records. AGENTS.md instructs
  Codex to run the actual `./knodexa context B.2 --json` binary. Raw events confirm
  context retrieval occurred. Codex still performs the coding with its native
  tools; Knodexa supplies memory.
- Native resumed: project requirements are supplied to a seed chat and inherited
  through `codex exec resume`. This tests native session continuity. The seed has
  the relevant facts but no unrelated image history, so its context presentation
  differs from the fresh-session arms.

The task was to repair a Python expiry validator while preserving its bool API,
handling malformed inputs, rejecting bool/string/float timestamps, enforcing
seven seconds of clock skew, and preserving caller dictionaries. Each workspace
had identical starting code and two smoke tests. Codex could add its own tests.
A separate grader withheld from the workspace applied the same 20 edge cases
covering malformed data, timestamp types/ranges, skew boundaries, exact bool
returns, and mutation. Those counts reflect independent checks, not the number
of tests generated by the agent.

Both fresh arms ran with workspace-write permissions. Native resume initially
received read-only permissions because the resume command lacked the explicit
sandbox configuration. That trial is excluded; the corrected invocation enabled
workspace-write. An initial Knodexa run lacked the distractor corpus; it too was
excluded and replaced. Initial logs and observations are retained under
`*_initial.*` and `initial-results.json` for transparency.

Generated background Codex memories were disabled to prevent cross-arm
contamination. This does **not** evaluate enabled Codex local memories, desktop
read_thread/list_threads tools, long-term memory generation, or multi-task
recovery after compaction. It is not a benchmark of every Codex internal tool.
The native fresh arm is a competent baseline with explicit durable instructions,
not a forced full-document token dump.

## Evidence and limits

`results.json` records CLI-reported usage and independent acceptance results.
`*.jsonl` preserves tool calls, model responses, and completion usage.
`*_expiry.py` preserves each final implementation. `live_eval.py` in the parent
audit directory supplies the task, facts, fixture setup, grading, and execution.
The background cache and service environment were not reset; trial order was
not randomized and there are no repeated runs or confidence intervals.

The practical conclusion is limited: repaired Knodexa can supply useful context
to a real Codex coding session, but this pilot shows no success-rate improvement
and does not support the earlier claim of lower total token usage. A larger
comparison must include multiple repositories, task switches, failures, and
repetitions; match memory-generation costs and enable Codex memories as a
separate arm before claiming cross-session superiority.
