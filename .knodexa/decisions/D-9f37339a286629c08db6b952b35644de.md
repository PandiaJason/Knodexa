## Rationale
Sync already scans every canonical record. Replacing derived tables in one SQLite transaction reconciles deletions and removed associations while preserving the previous snapshot if canonical parsing fails. This prioritizes correctness; large-project throughput has not been benchmarked.

## Constraints
- Canonical files remain the source of truth
- Malformed records abort synchronization instead of silently deleting knowledge

## Rejected alternatives
- Keep upsert-only sync: retains removed constraints and deleted nodes
- Drop schema outside the transaction: loses the previous snapshot on failure
- Implement incremental change tracking now: adds complexity beyond the existing full-scan design
